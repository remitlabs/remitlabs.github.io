How to audit your Claude Code skills

Find your installed skills, review their access and decide which versions to keep.

Prahalad Singh2026-11-088 min read

Run npx @remitlabs/cli@latest start. Remit scans the agent directories it recognizes and opens a local report with the most severe findings first. The scan leaves your skill files unchanged. npm may download Remit to run the command.

This guide explains the results, the checks you can run next and the limits to consider before approving a skill.

Where Claude Code keeps skills

Check every directory your agent uses. Skills can be stored in your home directory, a project or a plugin.

  • User-level skills. Stored in your home directory and shared across projects.
  • Project-level skills. Stored in .claude/skills inside a repository.
  • Plugin and marketplace skills. Installed through a plugin or copied from a registry such as skills.sh.
  • Other agent directories. Check the locations used by Codex, Cursor or OpenCode if you use those agents.

The same skill may appear in several directories. Check each copy because they can update independently.

Run the audit

$npx @remitlabs/cli@latest start

The first run discovers the agent directories it knows about, scans each skill, and starts a local app on 127.0.0.1:8787. On the machine this was built on, that produced:

123 skills across 4 agent directories
114 duplicate registrations
~15,238 tokens of skill text in eager mode
3 skills needing review
0 files modified

These measurements come from the founder's computer. Your results depend on the skills and agents you use. Review the installed files, repeated entries and findings in your own report.

Four things to review

1. Risky patterns in the skill's own files

The scanner checks 64 patterns in SKILL.md and its scripts. Examples include downloaded shell commands such as curl … | sh, access to ~/.ssh or .env, hidden characters and instructions to bypass approval. Read the matched code before allowing the skill to load.

2. Declared versus observed behavior

Compare the skill's stated purpose with its instructions and code. With Docker or Podman available, you can request a test in a temporary container. Remit uses fake secrets and a logging proxy to record file writes, network destinations, shell commands and credential access.

Review unexpected access, such as a skill that claims to work offline but opens a network connection. The test records one run. Another computer or a later trigger can produce different behavior.

3. Duplicates and stale copies

The example contains 114 repeated registrations. Duplicate entries are worth reviewing because

  • the same skill may need maintenance in several places.
  • copies can become outdated independently.
  • a fix or revocation may not reach every copy.
  • repeated instructions can consume additional model context.

4. Context cost

Loading every skill upfront uses model context on each prompt. On the founder's computer, 123 skills used about 15,238 tokens. On-demand routing used about 150 tokens by exposing a short index and loading skills when needed.

Check whether your agent needs all those instructions on every prompt.

What to do about what you find

After reviewing the report, keep a record of approved versions and review later changes.

Pin what you keep

A digest is a hash that identifies the exact skill version. Pinning saves it in a lockfile so you can compare a later update with the version you reviewed.

skillctl status
skillctl explain summarize-notes
skillctl pin summarize-notes

Review updates

A reviewed skill can change in a later release. When its content hash changes, Remit compares the update and flags changed behavior for review.

Park or remove what you do not use

Remove unused skills from the active set to reduce the instructions your agent can load. skillctl park retains the evidence. skillctl uninstall records removal. Hand-installed files need separate attention.

Route instead of loading everything

The MCP router loads skills on demand and checks policy and revocation status before loading them. Use it to reduce the skill text added to every prompt.

Keep revocation up to date

Remit verifies a signed list of withdrawn or changed versions. After sync, the router blocks revoked versions. Sync removes Remit-managed copies and identifies hand-installed copies for parking with a removal note. Check that each computer receives updates.

What this audit does not prove

Read these limits alongside the findings.

  • A finding is a rule match that needs review. A scan without findings can still miss harmful behavior.
  • A container test records one observed run. It can miss later triggers or behavior that differs on another computer. Container isolation also has limits.
  • The test records activity by default. Network blocking requires a list of allowed destinations. The proxy records traffic but cannot read encrypted TLS content.
  • File checks can be incomplete when files are oversized, unreadable or symlinked. The report identifies that missing coverage.

The report helps you see what is installed, what access it requests and what changed. Use it to decide what to inspect, pin or remove. Review the missing checks before approving a skill.

Do it once, then put it on a schedule

Repeat the scan when a skill changes or someone installs a new one. A regular review can help you catch missed changes and apply revocations.
