Run a scan and read your results.

Remit checks the skills your AI coding agents use. Start with a file scan and review the local report. You can then test behavior in a container, save an approved version and block revoked versions.

Install

$npx @remitlabs/cli@latest start

start scans your real agent skill directories, starts the local app on 127.0.0.1:8787, and opens the reports view with the highest-severity findings first. The scan leaves your existing skill files unchanged. npm may download Remit to run the command. See the 26-second demo to see the scan, reports and version controls.

For the Claude Code hook, use a global install so its command remains available after npm clears its temporary cache.

npm i -g @remitlabs/cli
skillctl setup

Use Node.js 22.5 or newer. Remit uses its built-in SQLite support. Docker or Podman is optional and enables container tests. With file checks alone, decisions stay unknown where behavior has not been tested.

First run

The first run does three things:

  • Discovers skill directories for Claude Code, Codex, Cursor, OpenCode, and other SKILL.md readers.
  • Scans each skill with 64 static rules and records a content digest.
  • Reports findings, duplicates, declared scope, and context cost in the local dashboard.

The scan reads your existing skill files without changing them or uploading their content. A container test runs only when you request it and Docker or Podman is available.

CommandWhat it does

skillctl auditAudit installed skill directories.
skillctl add owner/repo@skillReview the exact version, evidence and decision before installing.
skillctl statusList skills and their current status.
skillctl explain <name>Explain the decision, missing checks and report limits.
skillctl canary <dir>Test behavior in a temporary container using Docker or Podman.
skillctl syncVerify and apply the signed revocation list.
skillctl reportExport a report of installed skills and findings as Markdown or JSON.
skillctl scorecard <name>Show risk findings, test results, pinned versions and evaluation evidence.
skillctl hook-guardCheck tool calls through the PreToolUse hook. It records activity until REMIT_ENFORCE=1.
skillctl find "ship to prod"Search your local skills by meaning.
skillctl stopStop the local app.

The MCP router checks a skill before loading it. It refuses blocked skills. Review-level skills load only when REMIT_MCP_ALLOW_REVIEW=1. Skills without receipts can still load by default. Set REMIT_MCP_REQUIRE_EVIDENCE=1 to require evidence.

Concepts

  • Skill. An instruction file named SKILL.md, with any scripts or assets your agent can load.
  • Remit. The actions a skill says it needs, including reading files, writing files, network access and running commands.
  • Digest. A content hash that identifies the exact version of a skill.
  • Receipt. A report tied to a specific skill version. It records findings, completed checks and limits.
  • Lockfile. A record of approved versions that helps identify later changes.
  • Canary. A test in a temporary container using fake secrets and a network logging proxy.
  • Revocation feed. A signed list of withdrawn or changed versions that Remit verifies and applies.
  • MCP router. The component that checks policy and revocations before loading a skill for your agent.

The receipt

A receipt shows why Remit reached a decision. It lists rule matches, container results when available, the exact version and its revocation status. Read its missing checks as well as its findings.

{
  "name": "summarize-notes",
  "remit": { "read": ["~/Documents/notes/**"], "write": [], "network": [], "exec": [] },
  "evidence": "static clean · canary 0 outbound",
  "sha256": "9f8e…",
  "limits": "one observed run · not a guarantee"
}

A rule match needs review. Even a report without findings can miss harmful behavior. Use the report to decide what to inspect, pin or remove.

Troubleshooting

No Docker or Podman

File checks still run. Behavior remains unknown where it has not been tested. Install Docker or Podman to run a local container test.

Node version

Remit needs Node 22.5+ because the local index uses node:sqlite. Check with node -v. Use a version manager if needed.

The hook disappears after npx

Install globally (npm i -g @remitlabs/cli) and re-run skillctl setup. The npx cache can be cleaned between runs.

Windows

The CLI supports Windows. Container and hook paths have had less testing there. If something fails, include skillctl doctor --json output in an issue after checking it for private information.

Nothing found

Point the audit at a directory, or check that your agent stores skills in a path Remit knows. skillctl doctor lists the detected agent directories.

Limits

  • A finding is a pattern to investigate. File checks alone cannot establish whether a skill is safe.
  • A canary receipt records one container test. A skill may behave differently on another computer or when a condition changes. Container isolation also has limits.
  • The canary records activity by default. Restrict network destinations with --egress allowlist. It sees traffic through the HTTP(S) proxy but cannot read encrypted TLS content. It runs without the agent or model.
  • Static coverage can be partial when files are oversized, opaque, or symlinked. The scan reports that state; it does not silently treat it as clean.

Review the report together with its limits before approving a skill.
