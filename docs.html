Install, audit, and understand the receipt.

Remit is a local-first CLI and dashboard for AI agent skills. It scans the skills your agents already use, records static findings, runs a behavioral canary when a container is available, pins installs by digest, and blocks revoked digests at load time.

Install

$npx @remitlabs/cli@latest start

start scans your real agent skill directories, starts the local app on 127.0.0.1:8787, and opens the reports view with the highest-severity findings first. Nothing is installed or modified by the scan. See the 26-second demo for the audit → explain → pin → revoke loop.

If you plan to use the Claude Code hook, install globally so the hook path survives npx cache cleanup:

npm i -g @remitlabs/cli
skillctl setup

Requirements: Node.js 22.5 or newer (the local index uses node:sqlite). Docker or Podman is optional. Without a container runtime, Remit runs static-only and reports unknown where behavioral evidence is missing.

First run

The first run does three things:

  • Discovers skill directories for Claude Code, Codex, Cursor, OpenCode, and other SKILL.md readers.
  • Scans each skill with 64 static rules and records a content digest.
  • Reports findings, duplicates, declared scope, and context cost in the local dashboard.

It does not install, modify, or upload anything. The canary only runs when Docker or Podman is present and you ask for it.

skillctl syncVerify and apply the signed daily feed.
skillctl reportAuditor-facing fleet posture (markdown or JSON).
skillctl scorecard <name>Risk + canary + lockfile + eval evidence.
skillctl hook-guardPreToolUse guard; observe-only until REMIT_ENFORCE=1.
skillctl find "ship to prod"Semantic search over the local index.
skillctl stopStop the local app.

The MCP router enforces the same assessment at load time. Hard blocks always refuse. Review-level skills refuse unless REMIT_MCP_ALLOW_REVIEW=1. Legacy skills with no receipt still load unless you opt into REMIT_MCP_REQUIRE_EVIDENCE=1.

Concepts

  • Skill — a SKILL.md package plus optional scripts and assets that an agent can load.
  • Remit — the declared scope of what a skill may do: read, write, network, exec.
  • Digest — a content hash that identifies the exact skill bytes.
  • Receipt — a digest-bound record of what was observed in one run, including coverage and limits.
  • Lockfile — the pinned digest record used to detect rug pulls.
  • Canary — a disposable-container run that observes behavior with fake secrets and a logging proxy.
  • Revocation feed — a signed list of revoked or drifted digests that clients verify and apply.
  • MCP router — the load-time gate that applies policy and revocation before a skill reaches the model.

The receipt

Every verdict ships with its evidence: the rule hits, the canary diff when it ran, the pinned digest, and the signed-feed status. A receipt is one observed run. It is re-runnable, and it states what it could not see.

{
  "name": "summarize-notes",
  "remit": { "read": ["~/Documents/notes/**"], "write": [], "network": [], "exec": [] },
  "evidence": "static clean · canary 0 outbound",
  "sha256": "9f8e…",
  "limits": "one observed run · not a guarantee"
}

A finding is a rule match, not proof of intent. A clean receipt is not proof that a skill is benign. Use it to decide what to inspect, pin, or remove — not as a safety badge.

Troubleshooting

No Docker or Podman

The static scan runs; behavioral evidence is unknown. Install a container runtime for a canary receipt, or use the hosted canary when the team tier ships.

Node version

Remit needs Node 22.5+ because the local index uses node:sqlite. Check with node -v. Use a version manager if needed.

The hook disappears after npx

Install globally (npm i -g @remitlabs/cli) and re-run skillctl setup. The npx cache can be cleaned between runs.

Windows

The CLI runs on Windows, but some container and hook paths are less tested. If something fails, open an issue with skillctl doctor --json output.

Nothing found

Point the audit at a directory, or check that your agent stores skills in a path Remit knows. skillctl doctor lists the detected agent directories.

Limits

  • A finding is a rule match. It is not proof of intent, and a clean scan is not proof that a skill is benign.
  • A canary receipt is one observed run in a container. It is not a guarantee that the skill cannot escape, exfiltrate, or behave differently on another host.
  • The canary is observer-first by default. It enforces egress destinations only when you pass --egress allowlist. It observes HTTP(S) proxy traffic, not TLS bodies, and it does not run the agent or the model.
  • Static coverage can be partial when files are oversized, opaque, or symlinked. The scan reports that state; it does not silently treat it as clean.

Remit is defense in depth, not a clean bill of health.
