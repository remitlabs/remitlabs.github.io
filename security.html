What Remit checks.
What you still need to review.

Remit records where a skill came from, checks its files and identifies the version you reviewed. Optional container tests show what happened during one run. Each report states which checks ran and what they missed.

How the checks work

Where it came from

Remit records the registry, repository or local source. Review that source alongside the scan findings.

The exact version

Each assessment identifies the exact version checked using a content hash. A changed version needs a new assessment.

64 rules

Remit checks SKILL.md and scripts for patterns such as secret-file access, downloaded shell commands and hidden instructions. Each match needs review.

One observed run

A temporary container uses fake secrets, strace and a logging proxy to record credential access, network destinations, file writes and shell commands. It records activity by default.

Allow, monitor, review, deny

Each decision includes its reason and missing checks. Loading a skill marked for review requires an explicit opt-in.

Block withdrawn versions

Clients verify an Ed25519-signed revocation list. The MCP router blocks listed versions after receiving the update. Sync also identifies hand-installed copies that need attention.

What the 64 rules look for.

The package includes the rule names and severity levels. Use them to locate the code or instruction that triggered a finding.

Risks to review

prompt injection

A SKILL.md can instruct an agent to read credentials or send data online. The instructions themselves can cause harm.

setup commands

A setup instruction can ask you to download and execute a program. Review those commands before running them.

changed version

A skill can change after you review it. The lockfile identifies version changes, and the update comparison helps you review what changed.

hidden payloads

Hidden characters and encoded instructions can conceal content. Oversized or compiled files can leave gaps in the scan.

excess access

Compare the file and network access a skill requests with what a container test observes.

outdated copies

Copies across agent directories can become outdated independently. Track their versions and revocation status.

A scan without findings can still miss harmful behavior. Read the coverage and limits on each receipt.

Data handling

Local scan

The file scan, local index and container tests run on your computer. The local scan leaves skill content on your machine.

Local dashboard

Binds to 127.0.0.1:8787. Nothing is exposed to the network by default.

Self-hosted API

Runs on your infrastructure with Postgres, PGlite or SQLite.

Hosted team tier

In development. Before general release, I plan to publish the data flow, service providers, retention policy and data processing agreement.

Telemetry

Telemetry is opt-in and collects aggregate activation events. It excludes skill content, file paths and code.

Deletion

The proposed hosted-service terms provide JSON or Markdown exports for 30 days after cancellation, followed by deletion on request.

Report a vulnerability

Please do not open a public issue for a security problem. Email singhgaurprahalad@gmail.com with [security] in the subject and include the package version, a minimal reproduction, and the impact. I aim to acknowledge within 72 hours.

Machine-readable contact: /.well-known/security.txt. There is no bug bounty yet; I will credit reporters who want it.

Status

The local CLI is available in public beta. The hosted team service is in development.
